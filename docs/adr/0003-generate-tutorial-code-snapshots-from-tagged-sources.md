# DocCチュートリアルのコードを、行ごとにステップ番号を付けたソースから生成する

## Decision（決定事項）

### 決定事項

`AppFeature.docc` のチュートリアルに載せるコードは、`tools/tutorial-code/seq/*.seq` に
「各行がどのステップから（どのステップまで）存在するか」を書いたソースとして管理し、
`tools/tutorial-code/generate.py` でステップごとのスナップショット
（`Tutorials/TutorialArt/Code/<名前>-NN.<拡張子>`）を生成する。
1ステップで足す行は、空行と閉じ括弧だけの行を除いて5行以内、空行以外で6行以内とし、
生成スクリプトが超過をエラーにする。

### 比較・検討内容の要約

完成形のファイルを1つだけ置く案（前回の形）では、どの行の話をしているかが読み手に伝わらなかった。
ステップごとのファイルを手で書く案は、133ファイルを同期し続ける手間が大きい。
1つのソースから生成し、行数と参照の整合を機械的に確かめる案を採用した。

## Context（経緯・背景情報）

### 背景

チュートリアルを8章に広げ、DocCの差分ハイライト（前のステップから変わった行だけを光らせる機能）を
使って、ステップの説明とコードの行を対応させることにした。
DocCは `@Code` の `previousFile` で指定したファイルとの差分をハイライトする。

### 課題

1. **ステップが進むたびにファイル全体を書き直す必要がある**
   - `MemoEntity` は第2章から第7章まで13ステップかけて育つ。手で13ファイルを書くと、
     途中の1行を直すたびに後続の全ファイルを直すことになる。
2. **「1ステップ5行程度まで」を人の目で守り続けるのは難しい**
3. **`.tutorial` 側の参照ミスに気づきにくい**
   - `previousFile` が1つ前のステップを指していないと、ハイライトが崩れるだけでビルドは通る。

## Consideration（比較・検討内容）

### 比較対象

| 案 | ソリューション | 概要 |
|----|----------------|------|
| 案1 | 完成形を1ファイル置く | 概念ごとに最終形のコードだけを載せる |
| 案2 | ステップごとのファイルを手で書く | `MemoEntity-01.swift` 〜 `-13.swift` を個別に編集する |
| 案3 | **行タグ付きソースから生成する** | `N|` / `N-M|` で各行の存在範囲を書き、スナップショットを生成する |

### 比較表

| 評価項目 | 案1 完成形のみ | 案2 手書き | 案3 生成 |
|----------|----------------|------------|----------|
| どの行の話か伝わる | 悪い | 良い | 良い |
| 途中の行を直す手間 | 小さい | 大きい（後続ファイル全て） | 小さい（ソースの1行） |
| 1ステップの行数制限の確認 | 該当しない | 目視 | 自動（超過でエラー） |
| `.tutorial` の参照の確認 | 該当しない | 目視 | 自動（未参照・`previousFile` 誤りでエラー） |
| 仕組みの追加コスト | なし | なし | Pythonスクリプト1本 |

### 総合評価

| 案 | 総合評価 | 判定 |
|----|----------|------|
| 案1: 完成形のみ | 教材として使えないという指摘を受けた形 | **不採用** |
| 案2: 手書き | 保守の手間が大きく、制限と参照の確認も人頼み | **不採用** |
| 案3: 生成 | 追加はスクリプト1本で、制限と参照を機械的に保てる | **採用** |

## Consequences（結果）

### 期待される効果

1. 各ステップで足した行だけがハイライトされ、説明文と行が対応する。
2. コードの修正は `.seq` の該当行を直して `generate.py` を再実行するだけで済む。
3. 行数の超過、変化の無いステップ、どのステップからも参照されないスナップショット、
   `name` / `previousFile` の誤りを生成時に検出できる。

### 技術的リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| 生成物を直接編集してしまう | `Code/` を手で直すと次の生成で消える | `generate.py` は実行のたびに `Code/` を空にする。リポジトリ直下の `CLAUDE.md` に手順を書いた |
| スナップショットのSwiftはビルドされない | 教材用のコードで、`MemoStore` など未定義の型を参照している | 型名・シグネチャはApple公式ドキュメントとWWDC26のコードで確認した。実装は各章のプロンプトで別途行う |
