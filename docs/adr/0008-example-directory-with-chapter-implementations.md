# ios/ を実装前の土台として残し、全章を実装したコードを Example/ に置く

## Decision（決定事項）

### 決定事項

1. `ios/` は、ワークショップを始める前の土台（Siri連携が入っていない状態）のまま残す。
2. 第1章から第8章までのワークショップを実装し終えたコードを、`ios/` と同じ App + Library 構成で `Example/` に置く。
   DocC カタログは `ios/` にだけ置き、`Example/` には複製しない。
3. `Example/` は章ごとに1つのPRにし、前の章のPRの上に積む。章の差分がPRの差分としてそのまま読める。
4. iOS 27.3 beta の SDK にしか無い API（`CardSnippet`、`@AppIntent(.tool)`、Siri Evaluations など）は
   `#if SIRI_AI_PREVIEW` で囲み、Xcode 27.1 でもビルドとテストが通る状態を保つ。
5. チュートリアルの `MemoStore.shared` は、`Example/` では `AppFeature` の `MemoStore` として実装し、
   `MemoClient` を包む。intent の本体がチュートリアルのコードとほぼ同じ形で読めるようにするため。

### 比較・検討内容の要約

`ios/` に直接実装すると、ワークショップを始める土台が無くなる。別ブランチに実装を置く案は、
ブラウザで答え合わせをしたい読み手が辿りにくい。`Example/` に置けば `main` だけで両方が見える。

## Context（経緯・背景情報）

### 背景

- `ios/` は章末のワークショップで実装していく前提で、Siri 連携が入っていない。
- 自分で実装したものと見比べる完成形が無く、詰まったときに答え合わせができなかった。
- 手元の Xcode は 27.1 で、iOS 27.3 beta の API は SDK に無い。

### 課題

1. **土台と完成形を両方残したい**
   - ワークショップを進める人には土台が、答え合わせをしたい人には完成形が要る。
2. **beta の API がビルドできない**
   - 27.3 beta の API をそのまま書くと、27.1 の SDK でビルドが落ち、章ごとのPRを確かめられない。

## Consideration（比較・検討内容）

### 比較対象

| 案 | ソリューション | 概要 |
|----|----------------|------|
| 案1 | `ios/` に直接実装する | 土台を完成形で置き換える |
| 案2 | 実装を別ブランチに置く | `main` の `ios/` は土台のまま、`example` ブランチに完成形を置く |
| 案3 | **`Example/` に置く** | `main` に土台と完成形の両方を置く |

### 総合評価

| 案 | 総合評価 | 判定 |
|----|----------|------|
| 案1 | ワークショップの土台が無くなる | **不採用** |
| 案2 | 章ごとの差分は見やすいが、`main` から完成形が見えない | **不採用** |
| 案3 | 土台と完成形が並び、章ごとのPRで差分も残る | **採用** |

beta の API は、案A「27.3 beta の SDK が手に入るまで書かない」、案B「`#if SIRI_AI_PREVIEW` で囲んで書く」を比べ、
章の内容を欠かさずに 27.1 でビルドを保てる案Bにした。

## Consequences（結果）

### 期待される効果

1. 読み手は `ios/` でワークショップを進め、`Example/` で答え合わせができる。
2. 章ごとのPRの差分が、その章で足したコードの一覧になる。

### 技術的リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| `#if SIRI_AI_PREVIEW` の中身がコンパイルされない | 27.1 では型検査もされないので、誤りに気付けない | 27.3 beta の SDK が入ったら `siriAIPreview` を有効にしてビルドし直す。`Example/README.md` に未確認であることを書く |
| `ios/` と `Example/` の土台がずれる | `ios/` の土台を直しても `Example/` に反映されない | 土台を直すときは `Example/` にも同じ変更を入れる（`CLAUDE.md` に書く） |
| バンドルIDが同じ | 同じシミュレータで上書きし合う | 第8章のテストがバンドルIDで intent を引くので揃えておく。`Example/README.md` に書く |
