# チュートリアルのコードにコメントを書き、行数制限から外す。ベータのAPIにはタグを付ける

## Decision（決定事項）

### 決定事項

1. `.seq` のコードには、その行が何をしているかを `//` コメントで書く。
   コメントだけの行は、0003で決めた1ステップの行数制限（5行・6行）に数えない。
2. 説明文だけでコードを見せないステップは作らない。前のステップでコードを見せていたなら、
   説明に当たるコメントを足すステップにして、コードを表示し続ける。
   概念だけのセクションも、見取り図のコード（`ToolCandidates.swift` など）を用意する。
   コードにできるものが無い場合（Xcodeの機能の紹介など）だけ、説明文のみのステップを残す。
3. Siri AI Developer Preview（iOS 27.3 beta）で入ったAPIと機能を扱うセクションには、
   タイトルの末尾に `【iOS 27.3 beta】` を付ける。章全体が該当する第7章は章名とイントロにも付ける。
4. 途中にステップを挟むときは `tools/tutorial-code/shift.py` で後ろのステップ番号と
   `.tutorial` の参照をまとめてずらす。

### 比較・検討内容の要約

コメントを行数に数えると、1ステップで足せるコードが減り、ステップ数が倍近くに増える。
コメントは説明文の一部で、読み手が「何行のコードを足すか」の負担には入らないので、数えないことにした。

## Context（経緯・背景情報）

### 背景

0003のあとで、説明文だけのステップ（コードの表示が消える）が全8章で約35か所あり、
「前のステップでコードを表示していたなら消さないでほしい」「コードの無いところもなるべくコードで解説してほしい」
「コードにコメントを載せてほしい」「iOS 27.3 betaの機能が分かるようにタグを付けてほしい」という依頼を受けた。

### 課題

1. **説明文だけのステップでコードの表示が消え、前後のコードとの関係が分からなくなる**
2. **コードを読んでも、その行が何のためにあるかが説明文を読まないと分からない**
3. **正式リリース済みのAPIとベータのAPIの区別がつかない**
   - App Intentsのドキュメントでは、`ToolIntent`・`AppIntentTraits`・`GenerableEntity`・`IntentVisibility`・
     `ComputedProperty`・`DeferredProperty`・`SnippetRepresentableEntity`・`CardSnippet`・Siri Evaluationsが
     iOS 27.3 betaからになっている（2026-11-04にdeveloper.apple.comのドキュメントJSONで確認）。

## Consequences（結果）

### 期待される効果

1. どのステップでもコードが表示され、ハイライトで説明の対象の行が分かる。
2. コードだけを読んでも、各行の目的がコメントで分かる。
3. ベータのAPIを使う部分が、セクションのタイトルで見分けられる。

### 技術的リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| コメントが長くなり、コードが読みにくくなる | 行数制限が効かないので、いくらでも書ける | 1行で済む内容に絞る。説明文と同じことを繰り返さない |
| タグの付け忘れ・外し忘れ | 正式版が出るとベータではなくなる | 正式版のリリース時に `【iOS 27.3 beta】` で全文検索して見直す |
